# 강철 포화 (Tank Fortress)

포트리스2 방식의 1:1 2D 전차 포격전. 좌우로 움직이고, 각도를 잡고, 게이지를 채워 쏜다.
**땅이 파인다** — 그래서 상대를 죽이는 방법이 둘이다. 체력을 0으로 만들거나, 발밑을 들어내 떨어뜨리거나.

플레이: [`tank-fortress.html`](../../tank-fortress.html) 파일 하나를 브라우저로 열면 끝. 설치도 서버도 필요 없다.

| `Enter` | 턴 넘기기 |

## 이 게임이 실제로 어떻게 굴러가는가

### 딜레이가 턴 순서를 정한다

번갈아 쏘는 게 아니다. **누적 딜레이가 가장 낮은 전차가 다음에 쏜다.**
딜레이 64짜리 침탄을 쓰는 스팅어는 딜레이 206짜리 초신성을 쏜 노바가 한 번 쏘는 동안 세 번 쏜다.
그래서 무기를 고르는 일은 곧 **다음 차례를 사는 일**이다. 센 무기를 쏘면 오래 쉰다.

검증: `sim/test.html` 8절 — 스팅어 15회 vs 노바 9회 (비율 1.67).

### 지형은 높이맵이 아니라 비트마스크다

높이맵으로 만들면 포탄이 판 굴이 곧바로 메워진다. 그러면 "언덕 반대편을 아래로 뚫는다"는
포트리스의 핵심 재미가 통째로 사라진다. 그래서 픽셀 마스크를 쓴다 —
동굴이 생기고, 천장이 남고, 흙이 무너져 내린다.

`돌파 미사일`(천공탄·지저 관통)은 이 구조가 있어야 성립한다. 지형에 박힌 뒤 230px 를 더 파고들어
**상대 발밑을 통째로 들어낸다.** 체력을 깎는 게 아니라 서 있을 자리를 없앤다.

### 유도는 조준을 대신하지 않는다

유도탄은 **착탄점을 정해진 거리만큼 끌어당길 뿐이다.** 추격자가 150px, 추적탄이 90px.
살짝 빗나간 발은 붙지만, 크게 빗나간 발은 예산을 다 써도 표적에 못 닿는다.

이 값이 유도의 전부다. 조준 각도를 무료로 없애 주면 이 게임에 남는 게 없다 —
각도와 게이지를 맞추는 일이 게임의 전부이기 때문이다.

검증: `sim/test.html` 3b절 — 잘 쏜 발은 92px→20px로 당겨지고, 크게 빗나간 발은 94px로 그대로 남는다.

> 처음엔 표적 쪽으로 탄의 방향을 돌리게 만들었다가 두 번 실패했다.
> 중력이 있는 세계에서 표적을 곧장 겨냥하면 낙차만큼 반드시 못 미치고,
> 낙차를 보정해도 포물선을 타는 속도 방향을 매 프레임 쫓느라 궤적이 흔들려 **유도를 켤수록 더 빗나갔다.**
> 지금은 "이대로 두면 어디 떨어지는가"를 풀어서 그 지점을 미는 방식이다.

### 아이템은 하늘에서 떨어지고, 주우러 가야 한다

포트리스2 방식 그대로다. **3턴마다 헬기가 낙하산 상자를 떨어뜨린다.**
가만히 있으면 아무것도 안 들어온다 — 연료를 써서 걸어가 밟아야 얻는다.
**상자를 쏘면 안의 아이템도 같이 사라진다.** 적이 못 줍게 만드는 견제가 성립한다.

떨어지는 자리는 **체력이 낮은 쪽에 가깝게** 잡힌다(열세측 56회 vs 우세측 4회로 실측).
확률로 몰아주는 대신 **거리로 유리를 준다** — 앞선 쪽도 달려오면 주울 수 있으니 공짜가 아니라 선택이 된다.

이 구조가 이동에 두 번째 목적을 준다. 상자가 없으면 이동은 조준 각도를 바꾸는 용도뿐이다.

> 처음엔 턴 시작에 조용히 지급했다. 그건 포트리스가 아니라 그냥 난수 보상이었다 —
> 쟁탈도, 견제도, 이동할 이유도 생기지 않는다.

| | |
|---|---|
| ✚ 응급수리 | 체력 30 회복 |
| ◈ 차폐막 | 다음 한 방의 피해 절반 (낙하 피해는 못 막는다) |
| ⛁ 예비연료 | 이동력을 가득 채운다 |
| ⚡ 더블샷 | 두 발로 나간다. 딜레이 1.5배 |
| ✸ 강화탄 | 이번 발사 피해 1.6배 |
| ≋ 무풍탄 | 이번 발사는 바람을 무시한다 |
| ➹ 긴급이송 | 가까운 평평한 자리로 즉시 옮긴다 |

**아이템은 턴을 쓰지 않는다.** 턴을 잡아먹으면 "회복하려다 한 대 더 맞는" 구조가 되어 아무도 안 쓴다.
한 번에 4개까지만 지닌다 — 쌓아 두고 몰아 쓰는 것을 막는다.

### 판은 반드시 끝난다

70턴을 넘기면 서든데스가 시작된다. 매 턴 모두가 피해를 입고, 그 양이 턴마다 커진다.
회복 아이템이 들어오면서 양쪽이 서로를 못 죽이는 판이 실제로 나왔다(지하 공동에서 400턴을 넘겼다).
**판이 끝난다는 보장은 규칙이 져야지 플레이어의 선의에 맡길 일이 아니다.**

### 낙사가 진짜 승리 조건이다

넉백은 장식이 아니다. 가디언의 `충격파`는 피해 35에 반경 112, 넉백 2.6 —
**데미지로는 아무도 못 죽이지만** 절벽 옆에 선 상대를 밀어 떨어뜨린다.
전차의 `mass`(넉백 저항)가 `armor`(피해 감쇠)보다 중요해지는 순간이 이때다.

### 두 클라이언트가 같은 궤적을 그려야 한다

온라인 대전에서 서버로 보내는 것은 **"각도 52도, 파워 74로 쐈다"** 한 줄뿐이다.
포탄이 나는 3초를 서버가 중계하면 그 3초가 통째로 렉이 된다.
명령만 보내면 양쪽 화면에서 즉시, 동시에 포탄이 난다.

이게 성립하려면 두 브라우저의 계산이 **마지막 자리까지** 같아야 한다.
`Math.sin`/`cos`/`pow` 는 엔진마다 마지막 비트가 갈릴 수 있어서 쓰지 않는다.
IEEE754 가 완전히 규정하는 `+ - * /` 와 `sqrt` 만으로 삼각함수 테이블을 직접 만든다 (`logic/core.js`).

## 만져 보기

```bash
cd tank-src/tankfort
python tools/devserver.py          # 기본 8731. 포트를 바꾸려면 뒤에 번호를 붙인다
```

주소는 전부 `http://127.0.0.1:8731` 뒤에 붙인다.

| 경로 | |
|---|---|
| `/tank-src/tankfort/dev.html` | 게임 (스크립트 분리 로드 — 디버거에서 원본 줄 번호가 보인다) |
| `/tank-src/tankfort/sim/test.html` | 물리·승패·밸런스 검증 52항목 |
| `/tank-src/tankfort/sim/net-test.html` | 온라인 프로토콜 검증 12항목 |
| `/tank-src/tankfort/tools/sheet-studio.html` | 아트 시트 → `art/art.js` |
| `/tank-src/tankfort/tools/export-catalog.html` | `docs/catalog.json` 생성 (언리얼 툴셋이 읽는다) |

**반드시 이 주소로 열어야 한다.** 파일을 더블클릭해 `file:///` 로 열면 페이지는 뜨지만
시트 스튜디오의 &lsquo;개발 서버로 바로 저장&rsquo;과 카탈로그 내보내기가 동작하지 않는다.
(스튜디오의 `art.js 내려받기` 는 `file:///` 에서도 된다 — 서버를 안 쓰기 때문이다.)

빌드:

```bash
python build.py      # → tank-fortress.html (단일 파일)
```

node 가 있으면 `node sim/test.js` 로도 같은 검증이 돈다. 같은 파일이 양쪽에서 그대로 실행된다.

## 구조

```
logic/          규칙. DOM 참조 0. node 에서 화면 없이 한 판이 끝까지 돌아간다
  core.js         결정론 수학 (직접 만든 sin/cos/atan2, 시드 RNG)
  terrain.js      파괴되는 픽셀 지형 · 붕괴
  maps.js         전장 10종
  weapons.js      무기 25종 (선택 20 + 분열 자탄 5)
  tanks.js        전차 10종
  physics.js      포탄 궤적 · 전차 몸체 · 폭발 · 넉백 · 유도 · 보급 상자
  items.js        아이템 7종 · 헬기 투하 · 열세 보정
  match.js        딜레이 턴 순서 · 승패 · 서든데스 · 스냅샷/해시
  ai.js           궤적 탐색 조준 + 난이도별 오차
net/            room.js(프로토콜) + 전송체 2종 — 서로 교체 가능
render/         화면과 입력. logic 을 읽기만 한다
sim/            검증. 여기서 통과 못 하는 것은 화면에서도 통과 못 한다
server/         Render 용 릴레이 (100줄, 의존성 ws 하나)
unreal/         언리얼 에디터 툴셋 (전차·무기 표 감사, 전장 배치 편집)
tools/          개발 도구. 빌드 산출물에는 들어가지 않는다
```

**규칙은 `logic/` 에만 있다.** `render/` 는 한 줄도 승패를 바꾸지 않는다.
그래서 검증 스크립트가 통과시킨 판은 브라우저에서도 같은 결과가 나온다.

## 검증

```
sim/test.html      78항목 — 결정론 수학 · 지형 10맵 · 포탄 물리 · 무기 거동 · 유도 보정폭 ·
                            승패(체력0/낙사/넉백) · 전차표 · AI 전맵 완주 · 2:2/FFA ·
                            딜레이 순서 · 아이템 7종 · 보급 상자(투하·낙하·습득·파괴) ·
                            재현성 · 스냅샷
sim/net-test.html  12항목 — 방 개설 · 설정 전파 · 명령 중계 · 어긋남 감지와 복구 ·
                            한 판 전체 중계 완주(어긋난 턴 0) · 전송체 부재 처리
```

검증되지 않은 것을 분명히 해 둔다.

- **실제 Supabase/Render 통신은 검증하지 못했다.** 제작 환경에서 외부 접속이 막혀 있었다.
  프로토콜은 루프백으로 12/12 통과했으므로, 붙지 않는다면 원인은 프로토콜이 아니라 연결 설정이다.
- **언리얼 툴셋은 에디터에서 실행하지 못했다.** 언리얼 프로젝트가 없다.
  테스트 코드는 함께 있지만 한 번도 돌지 않았다 ([unreal/TankFort/README.md](unreal/TankFort/README.md)).
